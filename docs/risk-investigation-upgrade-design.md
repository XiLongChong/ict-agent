# 风险案件调查设计基线

## 1. 产品分工

当前系统由四个明确层次组成：

- 信号入口：当前包括 23 条确定性规则和模拟新交易；未来可替换为企业已有预警引擎，而不改调查内核。
- 调查 Agent：应收与库存案件都先发现当前主体可用的数据，再围绕假设使用统一的能力发现、业务标识
  搜索和受控证据查询三项工具。两类调查都把可判断的风险信号与仍未知的根因分开。
- 人工复核：判断风险成立、需要补充调查或确认无风险；Agent 不能自动执行任何业务动作。
- 飞书协同：新案件、调查完成/中断和复核完成自动发到绑定群，并通过深链接回到案件页；通知失败只记审计，
  不回滚案件事务。

系统不再提供通用数据问答、健康度评分、名单建议或独立项目审批链。经营看板保留为确定性辅助能力，
案件调查是唯一模型入口。

## 2. 案件与调查对象

应收案件按客户与最新月末聚合，只筛选非黑名单且仍有经营活动的深度超期或敞口增长。黑名单应收属于
已知存量风险，不进入主动发现队列。库存案件按物料、库存组织与最新季末聚合，可合并呆滞、大额增长、
增长伴随销售放缓三类规则。规则命中是调查起点，不是违约、坏账或具体滞销原因结论。

事前交易案件按客户和一类具体业务生成，模拟订单金额遵循该客户同业务历史分布，也可主动生成临界或
异常情景。分销、项目、服务云是交易级上下文，不是三个客户主体；一个客户可以在三个案件中分别出现。
模拟情景是演示信号，不是风险结论，也不会写入真实业务表。

案件库与业务库分离。业务库可以原子全量替换；案件、调查、证据和审核历史不会被数据导入覆盖。

## 3. 准确率优先的调查流程

1. 所有入口映射为 `InvestigationCaseInput 4.0`：`source` 记录创建入口，`subject_type` 记录主体粒度，
   `investigation_profile` 选择证据策略，`business_type` 只限定单一交易范围；另含观察期、敞口、信号、
   数据快照、阈值来源和数据质量状态。
2. DeepSeek `deepseek-v4-flash` 使用高强度思考模式；三类案件都先发现实时语义数据目录。
3. Agent 通过受控查询工具选择数据集、粒度、指标、时间窗口、排序和行数；必要时先在案件关联标识内
   搜索合同、订单或物料号。后端自动限定案件客户或物料/仓库，不允许任意 SQL。
4. 新证据改变假设、优先级或下钻方向时，Agent 在内部调整下一项查询，不对外发布形式化计划。
5. 每次查询生成唯一证据编号并保存参数、表格、期间、来源、口径和 warning。
6. 应收最低覆盖月度趋势、订单明细、销售回款及至少一种背景证据；库存完整覆盖历史、库龄和销售；
   事前交易覆盖拟交易、同业务历史画像、应收、同业务销售回款和授信。
7. Agent 先输出风险信号和监测项，再输出事实、候选原因、支持/反驳/缺失证据、限制和建议。
8. 输出校验器检查最低覆盖、引用完整性、状态语义和无依据结论；不合格则要求模型继续取证或修正。
9. 校验通过后保存报告并进入人工复核；中断则保存已有证据和 `UNRESOLVED` 根因。

## 4. 案件状态与退出

案件只表达调查流程，不承担工单或实际处置管理：

1. 任一信号入口生成案件后为 `PENDING_AGENT_REVIEW`（待 Agent 调查）。
2. Agent 启动后在存储层短暂标记为 `AGENT_REVIEWING`，用于阻止重复启动；API 和页面仍归入“待调查”，
   不增加第五种业务状态。
3. 完整或部分报告保存后为 `PENDING_HUMAN_REVIEW`（待人工复核）。
4. 人工确认风险成立后为 `ACTION_IN_PROGRESS`（处理中）。该状态表示调查完成并已交给业务处理，
   系统不再要求填写工单、复查日期或具体处置步骤。
5. 人工认为证据不足时回到 `PENDING_AGENT_REVIEW`，保留历史报告并允许重新调查。
6. 人工确认无风险、规则误报或数据问题时为 `CLOSED`（已关闭）。

`ACTION_IN_PROGRESS` 与 `CLOSED` 都不再允许调查或重复复核。前者保留“已确认存在风险”的业务语义，
后者明确表示审查后无风险。Agent 运行失败且没有形成报告时恢复为待 Agent 调查。

## 5. 结论语义

- `risk_assessment`：风险信号阶段、证据编号、主要驱动、反向信号和后续监测项。
- `facts`：工具直接证明的数据事实，每条至少引用一个真实 `evidence_id`。
- `SUPPORTED`：现有证据主要支持，必须列支持证据。
- `WEAKENED`：现有证据主要削弱，必须列反驳证据。
- `UNRESOLVED`：关键证据缺失或相互冲突，必须说明缺失或冲突。

白名单、授信额度、近期回款、信用保险只能缓释，不能覆盖逾期事实。客户历史展期不能解释当前应收，
只能使用当前客户、合同、订单和物料精确匹配的结果。销售变化可以支持或削弱库存原因假设，但不能
虚构促销活动、下游动销或下游库存。

数据没有核销、减值、司法结果、供货策略、银行未核销和项目验收记录，因此可以判断坏账风险是否
上升，但不能写成已确认坏账、一定不可回收、客户无回款能力、已停供或已进入诉讼程序。只对具体
根因和最终结果明确“无法判断”，不能把整案笼统降级为证据不足。

## 6. 可观察性

调查接口以 NDJSON 实时返回案件载入、数据发现、查询开始/完成、报告校验和最终保存。
前端展示工具活动和证据摘要，不展示私有思维链。报告保存完整工具轨迹，可刷新回放。

飞书是协同入口而不是第二套风控内核：卡片只展示案件状态、主体、业务类型、敞口和摘要，点击后进入同一
案件页。当前没有登录和飞书身份映射，因此卡片不提供复核按钮，避免匿名审批和伪造审核人。

如果模型在取得工具证据后失败，事件流先说明调查未完整完成，再返回已经保存的部分报告。尚无任何
工具证据时不生成无依据报告，此时返回安全错误，不泄漏异常细节。

## 7. 验收基线

- 应收与库存查询达到最低数据集/粒度覆盖，参数真实保存；相同查询及已被更宽时间窗口、更多指标和
  更多行完整覆盖的查询不得重复。
- `InvestigationCaseInput 4.0` 能独立表达来源、主体类型、调查策略和交易级业务类型，并完整携带数据快照、
  信号版本、阈值和数据质量。
- Agent 能随新增证据改变下一项查询，同时保持最低证据覆盖。
- 所有事实和假设证据编号真实存在。
- 假设状态满足支持、反驳或缺失语义。
- 风险信号有多项证据时必须给出判断；根因或最终结果无依据时局部弃答。
- 不出现已确认坏账、确定不可回收、已停供、诉讼、促销或下游库存等无依据事实。
- 页面能逐步显示工具、证据和校验，刷新后能回放轨迹。
- 完整与部分报告都可保存并进入人工审核。
- 工程测试使用 Pydantic AI 测试模型，不访问真实 DeepSeek。
- `backend/evals/` 的真实模型评测独立运行，不调用规则引擎。当前最终候选完成 6 案 × 2 轮，12 次
  调查均完整，并通过自动门槛、逐项人工语义复核与最终发布门槛；这只说明冻结评测集表现，不外推为
  线上总体准确率。

规则阈值仍以 `risk-rule-baseline.md` 为准，指标与字段口径仍以 `metric-contract.md` 为准。研究报告中的
候选复杂规则不因本设计自动启用。
