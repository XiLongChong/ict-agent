# 指标与证据契约

本文件是分析工具的业务事实基线。代码、提示词和页面不得各自复制一份不同口径。

## 1. 通用规则

- 金额单位完全遵循赛事官方数据字典和字段说明，当前工具内部统一为“元”；页面可格式化为万元/亿元，
  但必须标注单位。Agent 不处理或猜测另一套金额单位。
- 比例的结构化值统一使用 `[0, 1]`，页面显示时转换为百分比。
- “最新一期”取对应快照表 `MAX(快照日期字段)`，并在答案中显示实际日期。
- 应收和库存快照是时点余额，只能按一个快照期聚合；跨期趋势应先按每个快照期分别聚合。
- 分母为 0 时比例返回 `null` 并附警告，不返回 0% 假装可计算。
- 退货沿用销售流水的负数量和负金额，不擅自取绝对值或删除。
- 所有结论必须标注来源表；模型不能执行或展示自由 SQL。
- 每次成功导入必须生成七表内容哈希、模式指纹和稳定快照 ID；调查评测必须记录该身份。

## 2. 核心指标

| 指标 | 计算口径 | 来源 |
|---|---|---|
| 销售额 | `SUM(销售金额_折扣后_含税)`，保留退货负值 | `sales` |
| 销售成本 | `SUM(出库成本金额)` | `sales` |
| 含税粗算毛利 | 销售额 - 销售成本 | `sales` |
| 含税粗算毛利率 | 含税粗算毛利 / 销售额 | `sales` |
| 回款额 | `SUM(回款金额)` | `payments` |
| 最新应收余额 | 最新月末截面的 `SUM(应收金额)` | `ar_snapshots` |
| 最新超期应收 | 最新月末截面的 `SUM(超期应收金额)` | `ar_snapshots` |
| 超期率 | 最新超期应收 / 最新应收余额 | `ar_snapshots` |
| 30 天以上超期率 | `SUM(超期30天以上金额)` / 最新应收余额 | `ar_snapshots` |
| 60 天以上超期率 | `SUM(超期60天以上金额)` / 最新应收余额 | `ar_snapshots` |
| 展期动作数 | `COUNT(DISTINCT gkey)`，不是展期表行数 | `extensions` |
| 最新库存金额 | 最新季末截面的 `SUM(含税总价)` | `inventory_snapshots` |
| 呆滞库存金额 | 最新季末、`库龄 > 180` 的 `SUM(含税总价)` | `inventory_snapshots` |
| 合同签约额 | `SUM(销售金额)` | `contracts` |
| 项目出库额 | 项目合同号匹配后的 `SUM(销售金额_折扣后_含税)` | `sales` |
| 项目回款额 | 项目合同号匹配后的 `SUM(回款金额)` | `payments` |

## 3. 关联规则

- 客户主键：`customer_credit.客户编号_中台` 对应其余业务表的 `客户编号`。
- 项目合同：`contracts.合同编号` 对应销售、回款、应收的 `合同号`。
- 合同风险信号关联：优先按 `contracts.合同编号` 精确匹配销售、回款或应收中的 `合同号` 取得客户编号；没有交易关联时，仅在客户主数据名称唯一匹配时补充客户编号。多客户歧义或无法关联的合同不进入客户案件。
- 销售/回款/应收/展期最细勾稽：客户编号 + 销售订单号；有合同号时同时带合同号。
- 非项目类合同号为空或未命中签约表是正常现象，不能作为数据错误。
- 库存无客户维度，只能通过物料编码和库存组织与销售进行有限关联；不得声称某库存必然属于某客户。

## 4. 业务类型与事前交易口径

### 4.1 交易级业务类型

- 项目：销售订单类型为 `信产项目N` 或 `信产项目S`。
- 服务云：非项目订单且核算大类命中已维护的云产品名称，或名称包含“软件”“服务”。
- 分销：其余销售订单。
- 项目判定优先于服务云。例如核算大类包含“云”，但销售订单类型是 `信产项目N/S`，仍归入项目。
- 客户可能同时包含多种业务；业务类型不能升级为客户唯一标签，也不再生成独立“分析对象”或健康记录。
- 业务类型用于限定模拟交易的历史比较基线、Agent 的销售/回款取证范围，以及案件页面的业务上下文。
- 客户级应收规则不会按业务类型复制案件，否则会重复计算同一客户敞口；即使客户历史上只有一种业务，
  也不得把历史分布推断为案件的交易级 `business_type`。只有订单级/成交前信号才使用单一业务类型限定取证。

服务云单独划分，是因为样本确实包含腾讯云、微软 365/Azure、工业软件、专业服务等非实物交付订单。
这类业务既不符合项目订单的一次性交付结构，也不应与普通实物分销混合比较。现有数据只能支持交易、
毛利和回款分析，不能推断续费率、订阅留存、SLA 或服务可用性。

### 4.2 事前交易模拟

- 候选范围为存在正向历史订单的“客户 × 业务类型”；客户与业务类型可以由用户指定，也可随机选择。
- 历史订单金额按客户、业务类型和销售订单号聚合，保留退货后的净额，只使用净额大于 0 的订单形成分布。
- 大样本客户的订单分位数、最大值、毛利率中位数和回款账龄中位数由 DuckDB 在受控查询内完成聚合；
  Python 只接收统计结果和一笔由 seed 确定的历史订单样本，不绕过 10,000 行查询保护。
- `NORMAL` 从历史订单自助抽样后乘 `0.85–1.15`；`BORDERLINE` 为历史 P75 的 `1.00–1.25`；
  `ANOMALY` 为 `max(P90, 历史最大单)` 的 `1.50–2.50`。
- `RANDOM` 以 `80% / 15% / 5%` 选择上述正常、临界和异常情景；同一数据快照传入相同 seed 时，金额、
  情景和模拟编号可复现；快照变化后生成新的模拟编号，避免误用旧历史分布。
- 拟账期取历史回款账龄中位数并在 `±5%` 内扰动；预期毛利率取历史订单毛利率中位数并在 `±5%` 内扰动。
- 正向订单少于 5 笔、缺少毛利或缺少回款账龄时必须返回数据质量 warning；warning 会进入案件输入和报告限制。
- 模拟结果只写独立案件库，不写入销售、合同、应收、回款、库存、展期或授信事实表。
- 模拟器生成的订单先转换为 `PRE_TRANSACTION_REVIEW` 原始信号，经统一准入与案件组装后写入案件库；当前系统默认为演示模式，所有有效模拟订单都立案。
- 每笔模拟交易都会创建 `investigation_profile=PRE_TRANSACTION` 的案件。情景只表示它相对自身历史的位置，不等同风险成立；
  最终仍由 Agent 取证和人工复核。

## 5. 结构化证据

每个工具统一返回以下语义：

- `summary`：供模型读取的短事实，不加入推测。
- `columns` / `rows`：用于页面表格或图表的数据，最多 200 行。
- `sources`：实际使用的 DuckDB 表名。
- `period`：查询覆盖的日期或快照日期。
- `metric_definitions`：本次涉及的口径短句。
- `warnings`：空列表或数据限制，例如分母为零、无客户维度。
- `evidence_id`：调查运行时由系统生成的唯一证据编号。

调查报告必须区分风险信号、工具直接证明的事实、证据支持的合理推测和当前无法判断的根因或最终结果。
建议可以由模型组织，但不得伪装成数据库已有字段或已经执行的业务动作。

## 6. 当前风险案件规则

启用规则集为 `2026.08-v2`，当前共 **23 条确定性规则**（应收/合同/销售回款/授信域 16 条 + 库存域 7 条）。
逐条执行条件、阈值、命中分布与严重度见 `docs/risk-rules.md`（权威完整清单）；规则制定过程与回溯
说明见 `docs/risk-rule-baseline.md`。规则命中先经过准入漏斗，再由案件组装器形成候选调查案件；该链路不授权自动停供、调额、催收或结案。

补充规则：

- 应收观察实体为客户 × 最新月末；库存观察实体为物料 × 库存组织 × 最新季末。
- 黑名单未结应收视为企业已知存量风险，不进入当前主动发现队列；名单形成原因和时序仍不能由七表判断。
- `AR_OPERATING_EXPOSURE_BUILDUP` 中销售与回款差额只是方向性组合特征，不等同应收余额。
- 同一实体、观察期和规则集的多条命中合并为一个案件，优先级取最高值。
- 合同域命中统一按客户合并到 `AR|客户编号`；合同号保存在风险信号指标和案件上下文中，不生成 `CON|合同号` 案件。
- 同一规则集、观察期和实体重复扫描必须幂等，不重复创建案件。
- 原规则命中在调查和人工复核后继续保留。人工确认风险成立时案件标记为处理中，证据不足时退回
  待 Agent 调查，确认无风险或误报时关闭。
- `RULE_SCAN` 来源的历史 `CON|合同号` 案件属于已废弃主体键，在下一次规则扫描保存时连同孤立从属记录清理；其他来源和新的 `AR|客户编号` 案件不受影响。
- 案件队列的风险概况取最高严重度规则命中的 `rule_name`；风险等级对外只显示低、一般、高，规则内部
  的 `CRITICAL` 在 API 输出时归并为高，不改变规则命中和排序。

## 7. 调查证据契约

所有入口先映射为 `InvestigationCaseInput 4.0`，其中 `source`、`subject_type`、
`investigation_profile` 和 `business_type` 是互不替代的四个维度：来源描述创建入口，主体类型描述调查
对象粒度，调查策略选择证据路径，业务类型只限定单一交易范围。当前来源包括 `RULE_SCAN`、
`PRE_TRANSACTION_SIMULATION`、`EXTERNAL_ALERT` 和 `MANUAL`；本版本实际生产前两类。规则扫描成功基于
原子导入的七表快照，入口质量为 `PASS`；模拟交易
根据历史样本充足性返回 `PASS` 或 `WARNING`，不得把 warning 伪装成通过。

应收、库存和事前交易 Agent 先真实探测当前快照的语义能力，再根据已取得证据选择下一项受控查询。三项统一动作
为能力发现、案件范围内业务标识搜索和证据查询；只有证据查询生成 `evidence_id`。查询只允许选择
注册的数据集、粒度、指标、时间窗口、排序和返回行数，服务端自动限定案件主体并执行冻结口径，
不接受 SQL、物理字段、路径、正则或代码。

`receivables/month` 支持应收、超期、30 天以上超期、60 天以上超期、超期率和最大超期天数；
各月末独立聚合，30/60 天金额来自对应快照字段，不跨月累加。

- 应收月度趋势；
- 最新订单级应收与承诺日；
- 销售回款月度对齐；
- 深度超期信号：订单级展期精确匹配和当前授信；
- 敞口积累信号：正式合同闭环和当前授信；
- 其他应收信号：至少当前授信。

库存案件使用同一查询契约，固定覆盖 `inventory/quarter`、`inventory/age_bucket` 和 `sales/month`。
库存与销售只能支持“库存增长/老化与销售变化同时存在”的业务模式；缺少采购单、入库单、需求预测、
在手订单或下游数据时，集中补货、正常备货、需求转弱和具体促销原因必须保持 `UNRESOLVED`。

事前交易案件最低覆盖 `proposal/order`、`customer_profile/business_type`、`receivables/month`、
`sales_payments/month` 和 `credit/customer`。拟交易本身与历史分布是案件库证据，销售和回款必须限定到
同一客户、同一业务类型；授信与应收仍为客户级事实，Agent 必须明确粒度差异，不能声称它们只属于该业务。
报告必须先形成带证据引用的风险信号判断：

- `EARLY_WARNING`：多个经营指标方向一致，支持前瞻性风险信号；
- `DETERIORATING`：逾期、库龄或敞口等风险事实已经恶化；
- `LIMITED`：工具覆盖不完整，只能保留部分事实。

具体原因假设状态为：

- `SUPPORTED`：现有证据主要支持该候选原因。
- `WEAKENED`：现有证据主要反驳该候选原因。
- `UNRESOLVED`：关键证据缺失或证据相互矛盾。

每次证据查询保存 `arguments / summary / columns / rows / sources / period / metric_definitions /
warnings` 和唯一 `evidence_id`。事实必须引用至少一个本轮真实编号；假设只能引用本轮编号。无效引用、
缺少必要证据的状态、同一证据同时支持和反驳、重复查询或已被更宽指标覆盖的子集查询都会触发模型
重试。证据完整度由程序按信号要求的业务证据组计算，不接受模型自由生成百分比。

模型中断时可以保存部分报告：已经取得的查询摘要作为带引用的 facts；最低覆盖完成时保留规则与证据
共同支持的最小风险信号，具体原因固定为 `UNRESOLVED`；最低覆盖未完成时风险阶段为 `LIMITED`。
不得用模型常识补齐调查事实。

七表不支持的原因必须保持 `UNRESOLVED`：

- 银行到账但财务尚未核销；
- 项目未验收；
- 具体促销活动或下游客户库存变化；
- 工商司法等外部信用事件。
- 核销、减值或最终回收结果；
- 是否已经停供或客户是否丧失回款能力。

白名单、授信额度、信用保险或近期回款只能作为缓释证据，不能覆盖已发生的逾期事实。
