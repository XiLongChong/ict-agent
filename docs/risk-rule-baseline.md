# 当前风险规则基线与回溯说明

## 1. 基线状态

- 规则集版本：`2026.08-v2`，当前共 **23 条确定性规则**（应收/合同/销售回款/授信域 16 条 + 库存域 7 条）
- 单规则版本：`2.0.0`
- 数据观察期：应收截至 `2026-07-31`，库存截至 `2026-06-30`
- 数据规模：应收 24 个月末、库存 8 个季末、当前应收客户 35 家、最新库存物料组织组合 3,961 个
- 用途：发现仍在经营但风险正在显现的客户，以及库存与销售背离的早期信号
- 禁止用途：不得仅凭规则命中自动停供、调额、催收、计提，或认定违约、坏账和具体滞销原因

逐条规则逻辑、阈值与命中分布以 `docs/risk-rules.md` 为权威清单；本文档只保留基线与回溯结论。

金额单位按赛事官方数据字典统一为人民币元。快照只取单一观察期，不跨期累加。

## 2. 筛选原则

规则引擎只控制调查入口，不负责最终定性。当前版本采用以下原则：

1. 规则层只判断确定性条件并产出规则命中，不知道案件存储结构，也不直接创建案件。
2. 准入漏斗只做命中合法性、重复命中治理和同一主体分组，不复制或改写规则阈值。
3. 案件组装器把准入后的主体信号组装成一个案件，优先级只表示调查顺序，不表示已经确认最终损失。
4. 黑名单客户的未结应收属于已知存量风险，不再进入主动发现队列；系统不重复证明企业已经知道的事实。
5. 应收重点筛选未进黑名单、近三个月仍有销售或回款活动，但逾期较深或敞口继续扩大的客户。
6. 库存重点筛选金额显著增加、高库龄且无销售、以及库存增加同时销售明显下降的物料组织组合。
7. 规则集版本、实体和观察日期共同生成稳定案件编号；合同域命中先关联唯一客户编号并使用 `AR|客户编号`，合同号保存在信号与案件上下文；默认案件队列只展示最近一次规则集的结果。

## 6. Agent 与人工审核边界

- Agent 必须把“风险信号是否成立”和“具体根因/最终损失是否确定”分开。
- 多项经营指标方向一致时，可以给出有证据引用的早期预警或恶化判断；不能因为根因未知而把整案写成
  证据不足。
- 没有核销、减值、司法或回收结果时，可以说“坏账风险上升”，不能说“已确认坏账”或“一定无法回收”。
- 规则只负责生成待准入的命中，准入和案件组装后才进入待 Agent 调查队列。人工复核决定风险成立、需要补充调查或确认无风险；规则不自动
  推进案件状态，也不触发具体业务处置。
- 原始规则命中、调查证据和人工审核历史保留，但默认队列只展示最新规则集案件。

## 7. 已知限制与复查重点

1. 库存没有客户维度，只能按物料与库存组织关联销售，不能把某项库存风险归因给特定客户。
2. 授信只有当前状态，没有历史名单变化时间，不能判断黑名单与逾期的先后因果。
3. 无销售使用销售金额 `<= 0`，包含退货净额为负的情况；后续可根据人工标签决定是否单独分型。
4. 风险召回率、误报率和损失预测需要人工审核标签或赛事方结局标签，不能仅靠七表计算。
5. 后续版本应优先依据审核结果调整阈值和组合条件，而不是增加更多无法解释的规则。
