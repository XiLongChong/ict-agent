# 佳华智审使用说明

## 1. 系统主流程

```text
规则预警 / 外部预警 / 事前交易
              ↓
           统一案件
              ↓
      Agent 只读取证与报告
              ↓
           人工复核
              ↓
           飞书协同
```

信号负责说明“为什么值得调查”，Agent 负责核对跨系统证据和原因，人工负责最终业务判断。系统不会
根据规则或模型结论自动停供、调额、催收或修改名单。

## 2. 页面

### 风险总览 `/risk`

查看待调查、待复核、处理中、已关闭案件和总风险敞口。重新扫描只执行当前 23 条确定性规则；已存在的
同版本、同观察期、同实体案件不会重复创建。

### 案件队列 `/cases`

统一展示规则案件和事前交易案件。可按应收、库存、事前交易、状态和优先级筛选。一个客户可以因为不同
业务类型或不同信号进入多条案件；业务类型是交易上下文，不是额外“分析对象”。

### 事前交易 `/pre-transaction`

点击“生成新交易并创建案件”后，系统会：

1. 从有正向历史订单的“客户 × 业务类型”中选择候选；也可以手动指定客户和业务类型。
2. 根据历史订单金额、回款账龄和毛利生成一笔模拟新交易。
3. 把模拟交易写入独立案件库，不写入真实销售、合同、应收或授信数据。
4. 创建待调查案件，点击“启动 Agent 调查”进入同一个案件工作台。

`RANDOM` 的情景比例为正常 80%、临界 15%、异常 5%。正常、临界、异常只描述金额相对该客户同业务
历史分布的位置，不直接代表风险结论。

### 案件工作台 `/cases/{case_id}`

- 案件概况：查看信号来源、业务类型、数据截至、敞口和原始信号。
- AI 审查：观察能力发现、受控查询、证据返回和报告校验；页面不展示模型私有思维链。
- 人工复核：选择风险成立、需要补充证据或确认无风险，并填写审核人和依据。

调查中断但已经取得证据时，系统会保存部分报告；没有证据时不会编造结论。

### 经营分析 `/business`

查看确定性的销售、回款、应收、库存和合同指标。该页面不调用模型，也不是第二套风险评分系统。

## 3. 飞书

1. 在 `.env` 同时配置 `FEISHU_APP_ID` 和 `FEISHU_APP_SECRET`。
2. 发布企业自建应用并把机器人加入群。
3. 在群里发送“@机器人 绑定通知群”。
4. 可通过 `/api/v1/integrations/feishu/test` 测试消息发送。

绑定后，规则扫描发送一张聚合卡片，成交前新案件、调查完成、部分报告和人工复核完成发送案件卡片，
避免首次规则扫描按几十个案件刷屏。部署环境配置 `ICT_PUBLIC_BASE_URL`
后，卡片会提供案件深链接。当前系统没有登录和飞书身份映射，因此飞书卡片不直接执行人工审批。

## 4. 常见问题

**为什么不再有健康分析？**

健康评分与规则引擎都在做“按指标筛选风险”，会形成两套优先级和两套处置入口。当前设计把业务类型
用于限定比较基线和 Agent 取证范围，风险判断只通过统一案件闭环完成。

**服务云为什么单独分类？**

样本中确实有腾讯云、微软 365/Azure、工业软件和专业服务等非实物订单。它们不适合与普通分销订单
混合比较，也不是项目订单；但现有数据只能分析交易、毛利和回款，不能推断续费、留存或 SLA。

**事前交易是不是预测客户会违约？**

不是。它是一个可重复的“新订单进入系统”演示入口，让 Agent 在成交前检查拟交易、历史习惯、应收、
回款和授信。最终措施仍由人工决定。
