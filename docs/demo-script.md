# 当前版本演示脚本

1. 打开风险总览，说明规则引擎只负责筛出“值得调查”的候选案件，不自动停供、调额或业务定性。
2. 展示案件构成、风险敞口与规则版本，说明黑名单未结应收不再进入主动发现队列。
3. 打开一个仍在经营的非黑名单应收案件，先看规则命中和观察日期，再点击“开始 Agent 调查”。
4. 观察 Agent 先发现当前客户可用的数据集、粒度、指标和限制，再自主选择时间窗口与下钻粒度。
5. 观察查询开始、完成和证据返回；说明 Agent 会随新增证据调整下一步，但页面只展示可审计的工具过程，
   不展示形式化计划或模型私有思维链。
6. 先看“风险信号判断”：即使根因未知，也应判断早期预警或风险恶化；再区分确定事实、证据支持的
   原因假设和无法判断的具体事项。
7. 展开查询证据，展示实际查询参数、`evidence_id`、数据期间、来源、warning 和金额单位。金额统一按
   赛事官方数据字典中的“元”处理，不由 Agent 猜测。
8. 展开调查轨迹，说明刷新后仍可回放工具证据和报告校验结果。
9. 强调没有核销、司法、供货策略、银行未核销或项目验收数据时，Agent 可以判断坏账风险上升，但
   不能写成已确认坏账、一定不可回收、已停供或已进入诉讼程序。
10. 打开库存案件，说明库存增长必须同时检查历史、库龄和销售速度；赛事数据没有促销活动和下游库存，
    因此不能编造具体促销或下游压货原因。
11. 提交一次人工审核，演示持续观察、需要处置、误报和已解决状态，以及复查日期。
12. 最后打开经营分析，说明它是确定性指标看板，不消耗模型额度；通用数据问答已经删除。

如果演示中模型中断，继续展示部分报告：已有查询事实会被保存；最低证据覆盖完成时仍保留可验证的
风险信号，具体原因标记“无法判断”。这不是降级编造，而是系统主动保留当前调查进度。
