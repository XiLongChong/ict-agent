# 当前版本演示脚本

1. 先在飞书展示已绑定的协同群，说明企业现有规则/预警系统不需要被替换；本项目的创新点是接收信号后，
   Agent 自动跨业务数据调查并把过程、证据和结论交给人。
2. 打开风险总览并运行一次规则扫描。说明 23 条规则只创建“值得调查”的案件，不自动停供、调额、
   催收或业务定性。
3. 打开案件队列，指出规则案件与成交前案件使用同一状态机、同一调查 Agent 和同一人工复核流程。
4. 打开“事前交易”，选择随机客户和业务，生成一笔异常新交易。展示历史订单中位数、P90、拟金额、
   拟账期、预期毛利和数据质量；强调模拟记录不写入真实业务表。
5. 进入刚创建的案件，展示 `PRE_TRANSACTION` 来源、交易级业务类型和原始信号。业务类型用于选择正确
   历史基线；一个客户可以同时有分销、项目和服务云，三者不是三个主体。
6. 点击“启动 Agent 调查”。观察 Agent 先取得拟交易和同业务历史画像，再检查客户应收、同业务销售/
   回款和授信。业务演示默认查看工具、证据和校验；需要调试时，可在 AI 审查页展开最后一次模型请求与
   DeepSeek Chat Completions HTTP 请求与响应 JSON，核对脱敏请求头、`response_format`、英文系统指令、
   三项工具、累计 `messages`、`reasoning_content`、`tool_calls`、工具返回、重试和 SSE 响应事件；需要
   离线分析时下载完整事务 JSON。
7. 展开证据，展示 `evidence_id`、查询参数、数据期间、来源、口径和 warning。说明客户级应收/授信与
   交易级业务画像粒度不同，Agent 不会把客户总应收伪装成只属于某个业务。
8. 查看报告：先看风险信号阶段，再区分确定事实、证据支持/削弱的原因和无法判断的具体事项。正常情景
   也必须经过调查，场景标签本身不是风险结论。
9. 提交人工复核，演示风险成立后进入处理中、证据不足后返回待调查、确认无风险后关闭。
10. 回到飞书展示新案件、调查完成/部分报告和复核完成卡片。部署地址可访问时，卡片点击后回到同一案件页。
11. 再打开一个应收或库存案件，说明规则入口虽然不同，Agent 调查内核没有变化；未来替换企业预警引擎
    只需适配信号输入，不需重写 Agent。
12. 最后打开经营分析，说明这是确定性指标看板，不消耗模型额度，也不是健康评分或第二套规则引擎。

如果模型中断，继续展示部分报告：已有证据会被保存，未知根因保持 `UNRESOLVED`。这体现系统宁可局部
拒答，也不会为了给出完整故事而编造原因。
